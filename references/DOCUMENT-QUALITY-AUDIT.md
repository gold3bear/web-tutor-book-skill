## 1. 审计目标与边界

质量审计模式用于判断已有的 PDF、网页教程书、Markdown 手册或导出文档是否达到
指定用途的交付标准。先声明目标用途：

- `internal-note`：团队内部操作备忘；
- `public-quickstart`：对外发布的快速入门；
- `tutorial-book`：可独立学习、复现和长期维护的教程书；
- `print-publication`：适合打印或正式分发的出版物。

“合格”必须对应目标用途。内部可用不等于适合公开发布，视觉精美也不等于内容完整。

没有源稿、内容台账或对应网页时，不能声称已完成源内容覆盖审计。此时只能判断成品
本身的可用性，并把“内容保真未验证”列为证据限制。

## 2. 输入与证据

尽可能收集：

- 待审文档原件；
- 原始素材或源稿；
- 目标读者、使用场景和发布渠道；
- 对应网页、版本号、发布日期与产品文档；
- 术语表、内容台账和用户批准的省略；
- 最终 PDF、全部页面渲染图和 contact sheet。

PDF 审计至少保留以下证据：

- `pdfinfo` 或等价元数据结果；
- 每页文字提取长度、图片数、链接数和字体统计；
- 全部页面的渲染图；
- 带页码的 contact sheet；
- 封面、最长正文、截图密集页、流程图页和末页的原尺寸检查；
- 时间敏感链接和关键产品事实的在线核验结果。

## 3. 硬性门禁

出现任一 P0，公开发布结论必须为“不合格”，不能用总分抵消：

1. 安装入口、核心命令、关键链接或主要操作路径失效；
2. 关键步骤被裁切、遮挡、乱码或小到无法在正常阅读比例下辨认；
3. 关键说明只存在于截图，缺少可搜索、可复制的等价正文；
4. 暴露真实 Token、密码、个人数据、支付信息或其他敏感凭证；
5. 教程无法从输入走到可验证结果，缺少必要步骤或确认条件；
6. 存在会造成付费、发布、删除或数据外传的操作，却没有明确确认和风险边界；
7. PDF 无法稳定打开、页面空白、资源损坏或中文字体严重异常；
8. 对来源、费用、收益、权限或产品能力作出关键声明，却无法验证或与当前官方信息冲突。

P0 必须给出页码、可复现证据和修复后的验收条件。

## 4. 评分模型

在无 P0 的前提下按 100 分评分：

| 维度 | 分值 | 核心问题 |
|---|---:|---|
| 内容完整与任务闭环 | 25 | 是否覆盖前置条件、操作、验证、失败处理和下一步 |
| 准确性与可证伪性 | 15 | 链接、版本、费用、产品能力和来源能否验证 |
| 信息架构与教学设计 | 15 | 读者能否理解目标、顺序、章节关系和学习路径 |
| 可读性与无障碍 | 20 | 字号、截图、文本层、语言、替代说明和导航是否可用 |
| 视觉与出版质量 | 15 | 页面密度、留白、层级、裁切、图文关系是否专业 |
| PDF 技术质量 | 10 | 元数据、书签、链接、字体、标签、页面尺寸和优化 |

结论规则：

- `合格`：80–100 分，且无 P0；
- `有条件合格`：65–79 分，且无 P0；修复指定 P1 后才能公开；
- `不合格`：低于 65 分，或存在任一 P0；
- `无法判定内容保真`：缺少源稿或台账时附加的证据限制，不替代上述成品质量结论。

评分应解释扣分证据，不做脱离使用场景的机械打分。

## 5. 检查流程

### A. 确定用途

先写清目标读者、预期任务、发布渠道和合格标准。默认把公开下载的教程按
`public-quickstart` 检查。

### B. 技术扫描

1. 检查页数、尺寸、文件大小、标题、语言、创建工具和加密状态；
2. 提取逐页文字，标记空文本页、乱码、裸露 Markdown 和异常字符；
3. 统计图片、链接、字体大小、书签、命名目标和附件；
4. 标记“图片很多但可提取文字极少”的截图依赖候选页；
5. 检查链接是否真实可点击，不能只看页面上是否显示 URL。

可以运行可选脚本：

```bash
python3 <skill-dir>/scripts/audit_pdf.py input.pdf \
  --output review/document-quality-technical.json
```

脚本只负责产生候选问题，不能替代视觉与事实核验。

### C. 全书视觉检查

1. 渲染全部页面并生成 contact sheet；
2. 逐页检查密度、留白、截图大小、裁切、对齐和页序；
3. 原尺寸查看代表页，不能只看缩略图；
4. 对截图内的小字做正常阅读比例测试；
5. 区分“设计留白”和“内容被整体缩小后留下的无效空白”。

### D. 教学闭环

逐个任务检查：

- 开始前需要什么；
- 用户要输入什么；
- Agent 或系统会做什么；
- 付费、上传、发布和权限变化发生在哪里；
- 成功的可验证信号是什么；
- 失败时如何诊断、恢复或重试；
- 下一步是什么。

截图不能替代这些文字说明。

### E. 在线事实核验

链接、版本、模板数、价格、收益、提现、权限和服务地址具有时效性。审计时访问
官方来源，并在报告中记录核验日期。API 根路径对 `GET` 或 `HEAD` 返回 404
不一定代表服务失效；必须按官方方法或健康检查验证，避免误判。

### F. 分级与复验

按 P0、P1、P2 排序。修复后重新生成最终文档，重复技术扫描、全书渲染与代表页
检查；旧报告和旧 contact sheet 自动失效。

## 7. 常见误判

- PDF 被标记为 Tagged，不等于阅读顺序、语言和截图内容均可访问；
- 页面上显示 URL，不等于 PDF 中存在可点击链接；
- 截图原图分辨率高，不等于缩进 A4 后仍可读；
- 有文本层，不等于截图里的关键操作也能搜索和复制；
- 没有空白页，不等于页面空间利用合理；
- 文档只有八页，不等于内容简洁；也可能是关键说明被压进截图；
- HTTP `HEAD` 或 API 根路径失败，不等于实际授权接口不可用；
- 自动评分不能抵消 P0，也不能替代对目标读者完成任务的实测。
