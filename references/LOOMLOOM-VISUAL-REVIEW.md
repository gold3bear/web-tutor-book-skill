## 1. 定位与默认状态

把 LoomLoom 云端视觉审查视为可选的语义复核层，而不是网页教程书工作流的必需依赖。

- 默认关闭；
- 不影响本地制作、内容台账、浏览器审计、PDF 技术扫描和导出；
- 不替代本地越界、断图、链接、字体、PDF 标签、书签和内容覆盖门禁；
- 云端结论只能产生辅助建议，不能覆盖本地 P0；
- 用户未明确选择时，不安装、创建、上传或执行任何 LoomLoom 视觉审查任务。

适合 20 页以上、多个章节或多份文档的批量语义审查。少量页面优先由本地 Agent
完成，避免不必要的数据上传和费用。

## 2. 启用条件

同时满足以下条件才向用户提供该选项：

1. 本地已渲染全部待审页面；
2. 本地硬校验已经运行，且报告与截图清单可用；
3. 页面截图不包含未脱敏的 Token、密码、个人信息、支付信息或受限业务数据；
4. LoomLoom `doctor` 正常；
5. 服务模型目录包含用户明确选择的模型；
6. 存在兼容的官方、私有或 Market 审查模板；创建新 TemplateSpec 属于独立的持久化操作，必须走 TemplatePlan 与单独创建确认；
7. 模板的文本步骤能通过 `reference` 端口接收 `image/*`，并已经通过视觉冒烟测试。

不要因为模型家族通常支持多模态，就推断当前 LoomLoom 运行通道一定支持视觉输入。

## 3. 模型解析

用户当前偏好的候选模型是：

```text
google/gemini-3.1-flash
```

该字符串是偏好，不是可以写死的默认值。每次准备时查询：

```bash
loomloom template-spec models text-generate --include-unavailable --output json
```

规则：

1. 只有目录返回完全一致的 `modelId` 且 `available=true` 才能使用；
2. 精确模型不存在或不可用时，停止并展示服务实际返回的候选模型；
3. 不把 `google/gemini-3-flash`、`google/gemini-3.1-flash-lite`、preview
   版本或其他模型视为等价替代；
4. 用户明确选择替代模型后，重新记录模型 ID、目录状态和查询时间；
5. 目录存在仍不代表视觉可用，先用已知正常页、明显溢出页和截图过小页做小规模冒烟测试；
6. 冒烟测试也是云端运行，需要报价与确认。

维护一份项目级验证记录：

```text
model_id
catalog_available
image_reference_accepted
chinese_vision_passed
layout_detection_passed
structured_json_passed
tested_at
```

## 4. 数据准备与安全

本地先为每页建立审查包，一页对应一行：

```text
page_id
chapter
page_type
page_goal
rendered_screenshot
extracted_text
source_block_ids
previous_page_title
next_page_title
local_overflow_count
local_broken_image_count
local_min_font_size
local_text_length
local_image_count
local_whitespace_ratio
```

只发送完成当前审查所需的最小数据。上传前：

- 脱敏 Token、账号、个人数据、支付信息、内部 URL 和未公开业务数据；
- 删除浏览器标签、通知、路径和无关桌面区域；
- 保留本地原始截图与脱敏截图的映射；
- 列出将上传的页数、文件大小、数据类别和排除项；
- 页面发生修改后重新生成截图、审查包与报价。

使用图片资产引用时，遵循当前 TemplateSpec：

```text
asset_ref / image/*
→ initial_input
→ text-generate.reference
```

不要把本地路径、临时签名 URL 或大图片的二进制内容直接写入工作簿或长期日志。

## 5. 用户确认

### 第一次确认：启用与上传

在上传任何页面截图前展示：

```text
是否启用可选的 LoomLoom 云端页面截图辅助审查？

默认：不启用；现有本地制作与校验流程不受影响。
用途：批量检查页面层级、截图相关性、新用户理解和语义完整性。
计划上传：<page_count> 页脱敏截图及对应页面摘要。
不会上传：Token、个人信息、支付信息和未公开原始素材。
偏好模型：<requested_model_id>
模型状态：<available / unavailable / not yet verified for vision>
注意：云端结论仅供辅助，本地硬校验器保留最终裁决权。

如果同意上传并继续准备，请明确确认。
```

用户拒绝、忽略或未明确确认时，直接继续原有本地流程，不重复施压。

### 第二次确认：付费执行

上传、验证和预检只是准备，不授权云端运行。预检后必须展示：

- 模板或 Listing 名称与 ID；
- 私有模板版本（如适用）；
- 精确模型 ID；
- 输入来源与页数；
- 任务数；
- 服务返回的费用、币种和余额信息；
- 失败或部分完成仍可能产生的费用规则；
- 清晰的执行确认请求。

只有用户在当前对话明确确认后才能执行。输入、模型、模板、版本或页面变化时，
重新验证、预检、报价和确认。不要根据“这是测试”推断 Test Execution Mode。

## 6. 云端执行

推荐每页固定并行四个视角：

1. 新用户理解与任务闭环；
2. 内容保真与截图信息依赖；
3. 视觉层级、留白和截图相关性；
4. 术语、出版表面与相邻页面一致性。

再由一个汇总步骤输出结构化结果：

```json
{
  "page_id": "03-04",
  "semantic_status": "warn",
  "p0": [],
  "p1": [
    {
      "issue": "关键报价信息只存在于截图中",
      "evidence": "正文未说明币种和确认条件",
      "suggested_fix": "增加报价确认正文"
    }
  ],
  "p2": [],
  "rewrite_required": true,
  "confidence": 0.87
}
```

不要让云端直接修改页面源代码。第一阶段只生成审查结果和修复建议。

## 7. 结果合并与裁决

云端完成后：

1. 保留 `runId`、精确模型 ID、模板版本、输入快照和服务返回的实际费用；
2. 下载结构化结果，不把临时签名 URL 写入报告；
3. 本地按 `page_id` 合并结果；
4. 把云端结论标记为 `advisory`；
5. 用本地 DOM、PDF、内容台账和链接检查验证每个 P0；
6. 冲突时以可复现的本地事实为准，并记录冲突；
7. 修复页面后重新渲染并重新执行本地门禁；是否再次调用云端由用户重新选择。

最终报告说明：

- 是否启用云端审查；
- 上传页数与脱敏范围；
- 模型、模板、版本与运行 ID；
- 云端建议数量；
- 被本地验证、降级或驳回的结论；
- 费用与仍存在的限制。

## 8. 降级与失败处理

以下情况直接保留本地流程：

- 精确偏好模型不存在或不可用；
- 模型尚未通过视觉冒烟测试；
- 用户不接受替代模型；
- 没有兼容的审查模板；
- 页面含不能上传的数据；
- 无法在提交前得到费用与币种；
- 用户拒绝上传或付费执行；
- LoomLoom 服务、认证或网络异常。

降级不是失败。明确说明“已跳过可选云端审查，本地制作与发布验收继续正常进行”。
