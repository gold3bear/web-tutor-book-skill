## 1. 阅读模型

提供两条使用同一内容源的阅读路径：

- 翻页阅读器：按语义页推进，适合教学与浏览；
- 连续阅读：完整长文，适合搜索、复制、引用和打印。

需要 PDF 时增加同源打印视图：复用翻页版的封面与视觉页，让长正文可分页流动。具体执行前完整阅读 [`PDF-EXPORT.md`](PDF-EXPORT.md)。

不要维护多份手工内容。使用结构化章节数据或共享组件生成各视图，避免版本漂移。

## 2. 页面与响应式

- 桌面可采用 3:4、A4 或出版物比例，内容居中，边缘控件弱化。
- 手机不要强制桌面纸张比例；使用 `100dvh` 附近的全高页面，保留安全区。
- 解释正文允许自然段和小标题；不要把所有内容做成卡片。
- 代码与大表可以局部滚动，但页面必须明确显示“可滚动/可展开”。
- 除明确可滚动页型外，要求 `scrollHeight === clientHeight`、`scrollWidth === clientWidth`。
- 字体过小意味着需要增加页数，不是继续压缩。
- 不要对整页使用 `transform: scale()` 或统一缩放来修复溢出；它会造成页面缩在上方、下方大量留白。先拆页、调整网格或取消不必要的固定高度。
- 当流程图加入后正文空间不足，把“流程图”和“完整说明”拆成相邻语义页。视觉页不承担完整原文，正文页不被流程图占高。

## 3. 导航和状态

至少实现：

- 上一页/下一页；
- ArrowLeft、ArrowRight、PageUp、PageDown、Space；
- 手机左右滑动；
- 目录跳转；
- `#page=<id>` deep link；
- `hashchange`/`popstate` 双向同步；
- localStorage 断点续读；
- 连续阅读入口。

更新章节、页数或顺序后 bump 存储键版本，避免旧索引越界。

开发预览使用 HTTP 服务，例如项目自带的 `npm run dev` 或静态服务器。只有明确验证过单文件离线构建后，才把 `file://` 作为交付入口；白屏时先检查模块加载、资源路径、控制台错误和路由，不要误判为排版问题。

## 4. 可访问性

- 使用 `main`、`article`、`nav`、`header`、`footer` 等语义元素。
- 每页提供稳定可访问名称；目录当前页使用 `aria-current="page"`。
- 目录作为模态时管理焦点、Escape 关闭和背景不可交互。
- 图片提供有信息量的替代文本；装饰图标使用 `aria-hidden`。
- 支持 `prefers-reduced-motion`；动画结束后内容必须全部可读。
- 保证键盘焦点可见，复制按钮和外部链接可操作。

## 5. EPUB 导出

- EPUB 3 使用可重排 XHTML，不复刻固定像素网页舞台。
- 每章可拆成一个或多个 XHTML 文件，语义页可作为 section/分页提示。
- 内嵌目录使用 `nav epub:type="toc"`，封面、元数据和语言必须正确。
- CSS 使用相对单位；为代码、表格、图片提供窄屏降级。
- EPUB 与网页必须来自同一内容结构，并再次运行覆盖审计。

## 6. 视觉页、截图与 Prompt

### 独立视觉页

- 流程图、真实截图和信息图应有明确教学目的，并绑定源内容块。
- 图题说明“这张图证明或解释什么”，不重复标注“页面截图”“流程图”“信息图”。
- 视觉页与完整正文页相邻；需要先看结构时可把图放前一页，但不要显示“下一页阅读完整原文”之类编辑提示。
- Chapter Open 可以用本章核心流程填补结构，但不要为每章强行增加无信息增量的装饰图。

### 真实截图

- 优先使用用户提供或实际页面截取的清晰素材；记录 URL、日期或本地来源。
- 截图必须与相邻内容直接相关。真实但无关的截图仍然是不合格素材。
- 不伪造产品 UI、终端日志、报价、审核状态或运行结果。没有截图时使用明确标注的流程图，或说明证据暂缺。
- 为截图提供有信息量的 `alt`，使用可读图题说明场景边界；不要把一个扩展案例伪称为正文中的精确测试结果。
- 优化尺寸与格式，但保留足够分辨率；正文阅读所需的界面文字必须能放大辨认。

### Prompt 与引用块

- “你对 Agent 说什么”适合使用独立 Prompt 卡片或引用块，保留完整指令、URL、参数和确认条件。
- 正确渲染粗体、行内代码、代码围栏、列表和引用，不把 Markdown 标记直接显示给读者。
- 复制控件是可选功能，只在代码或长 Prompt 的复用价值明确时加入；用户要求移除后，全局组件、样式和最终构建都必须同步清理。

## 7. 出版表面清理

交付前逐页搜索并检查：

- 原始 Markdown：`**`、代码围栏、`[文字](URL)`；
- 编辑态说明：“完整原文”“可在页内继续阅读”“先看结构”“下一页阅读原文”；
- 重复类型标签：“页面截图”“流程图”“信息图”；
- 空按钮、失效复制控件、占位符、内部组件名；
- 术语漂移：品牌大小写、人物称谓、Agent 名称；
- 图片替代文本是否只是“截图”或文件名。

不要简单删除所有命中项。区分可见 UI、正文合法用词、替代文本和素材来源说明；重点清理读者可见但没有信息增量的标签。

## 8. 完工自检

内容：

- 覆盖审计 100% 通过；
- 随机抽查每章至少三个源块，对照最终文字无事实和限定条件损失；
- 连续阅读模式包含全部源内容；
- 无未经用户批准的省略。

交互：

- 目录、键盘、触摸、deep link、刷新恢复、前进/后退均通过；
- 首尾页按钮状态正确；
- 页面数量变化后旧存储不会越界。

视觉：

- 桌面、390×844、360×800 无意外裁切；
- 正文字号和行长适合长时间阅读；
- 没有紫粉渐变、emoji 图标、彩色卡片阵列等模板化 AI 味；
- 颜色与字体使用主题 token；
- 视觉图解解释关系，而不是替代内容。
- 真实截图与相邻教学任务相关，且没有伪造界面；
- 没有编辑态提示、重复类型徽标或裸露 Markdown；
- 图加入后没有把正文挤出页面，也没有通过整页缩放制造大块留白。

工程：

- 类型检查和正式构建通过；
- 控制台无项目错误和警告；
- 图片经过尺寸与格式优化；
- 在线版优先分离静态资源并缓存，离线单文件版作为独立构建；
- 报告 HTML/PDF/EPUB 大小和测试结果。
